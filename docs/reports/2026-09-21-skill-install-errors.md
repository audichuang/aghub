# 技能安裝錯誤與診斷日誌盤點

## 結果

`nas-container` 的來源內容被安全規則誤判，SourceDetail 又只顯示失敗目標數，讓使用者看不到後端已提供的原因。修正位於 `codex/skill-audit-errors`，未部署到已安裝的桌面程式。

| 範圍            | 已確認的問題                                                         | 修正                                                                                |
| --------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 安全掃描        | 同檔出現 `cat`、`.env`、`curl` 就升為 Critical，連寫設定與健檢也被擋 | 要求憑證讀取語法；保留明確 Python、JavaScript、shell 憑證讀取的攔截，模糊訊號仍警告 |
| 來源安裝        | 批次 HTTP 200 內的失敗列只顯示數量                                   | 通知包含技能、agent、原因；空白原因有備援文案                                       |
| GitHub 匯入     | 同技能多 agent 失敗只顯示第一筆；請求失敗可能留在收合區              | 顯示每個失敗 agent 的原因，請求失敗重新展開錯誤與重試區                             |
| 更新、清理 lock | 部分請求失敗只顯示固定文案                                           | 使用既有安全錯誤分類保留可顯示的後端原因                                            |
| API 日誌        | 批次安裝失敗仍只有 HTTP 200，缺少目標脈絡                            | 每個失敗列記錄操作、scope、技能、agent、原因；不記錄來源 URL 或轉送 token           |
| 日誌列表        | 永遠取最早 5,000 筆；本次實機 37,826 筆中看不到最新失敗              | 跨輪轉檔依實際時間排序，優先顯示最新的符合條件紀錄，標明顯示範圍                    |
| 日誌操作        | 讀取、統計、清除或匯出有忽略檔案錯誤的分支                           | 回報檔案操作失敗；部分清除失敗交代已清除數量；前端顯示原因與適用的重試              |
| 可存取性        | 部分錯誤沒有宣告，圖示按鈕只有 tooltip                               | 加入錯誤 live region、按鈕名稱與讀取重試                                            |

## 驗證

- 掃描回歸測試先失敗再修正；52 項 skill-audit 測試通過。涵蓋一般與緊貼重導向的 `.env` 寫入、Python 寫入、巢狀 JS 路徑，以及明確 Python 憑證讀取。
- 用實際 `nas-container` 來源副本呼叫共用 `guard_fetched_source(..., false)`：接受安裝，判定 `Suspicious`，23 個 finding，沒有 Critical。這是靜態掃描驗證，沒有執行 NAS 腳本。
- API 測試確認安全拒絕保留每個目標的技能、agent 與規則／相對檔名，拒裝不產生 Master 或 Referrer。
- 日誌整合測試先重現缺少目標紀錄，再驗證新增紀錄；同時確認原始 token、編碼 header 內容與 header 名稱不進 log。
- 前端 280 項測試、typecheck、ESLint、Prettier 通過；11 項日誌時間排序與 I/O 失敗的 Rust 測試通過。Rust fmt 與 API／桌面／skill-audit 的 Clippy（all targets、warnings 視為錯誤）也通過。
- 用真實前端與隔離 API 啟動頁面，在安裝 HTTP 邊界注入三個拒絕結果，實際點擊後可看見三個 agent 及掃描原因。另驗證最新日誌標示與模擬清除拒絕訊息。這些測試沒有安裝真實技能或清除使用者日誌。

## 界線

- 掃描仍是啟發式規則，沒有變成完整語言資料流分析器；未關閉安全掃描，也沒有加入全域略過開關。
- 批次通知沿用既有前三筆預覽與剩餘數量；完整失敗列留在 API 結果與診斷 log。
- 更新 API 保留既有內部錯誤遮蔽，新增前往「設定 > 日誌」查看命中規則的指引；沒有直接把任意內部錯誤字串公開。
- 這次盤點聚焦技能安裝／更新及共用診斷日誌，沒有改寫其他功能的錯誤架構。
